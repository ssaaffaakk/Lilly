One tool, four ways in

Built for Bosnian, not bolted onto it

Most translators file Bosnian under South Slavic and stop there — close enough to look right, wrong enough to leave you lost in the room. Lilly’s translator and listener are fine-tuned on Bosnian specifically, and every score above is measured against the untuned model underneath them.

Type it

Write a sentence in Bosnian or English and get it back in the other, instantly.

Say it

Press the microphone, speak, and hear Lilly’s answer read back to you.

Photograph it

Point your camera at a sign, a whiteboard, a menu — Lilly reads it and translates it.

Correct it

Tell Lilly when it’s wrong. Verified corrections go back into training, not a benchmark.

Nothing leaves your machine

Fetch the weights once. After that, Lilly never reaches the network again — no account, no upload, no API key. A correction you send is stored locally for review, not phoned anywhere.

Why I built it

“They told me I didn’t know Bosnian.
So I built the thing that understands it.”

I applied for an internship. They didn’t take me — not because my code was weak, but because I didn’t know Bosnian. I’d heard some version of that sentence before, in different rooms, and at some point language stopped feeling like a language and started feeling like a door I was always standing on the wrong side of.

Bosnian itself was never the problem. The tools were: most of them file it under one more entry in a South Slavic bucket, a different flag on the interface. Recognizing the region is not the same as understanding the language.

So I trained the models myself, measured every change against the untuned model underneath it, and published all of it — including the runs that say a change did nothing. I build things because when I hit a wall, I’d rather solve it than accept that it can’t be solved.
